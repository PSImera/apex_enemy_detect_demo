# Apex Legends Enemy Detector

> [English version](README.md)

Демо-приложение для просмотра результатов работы YOLOv8-моделей обнаружения врагов на видео геймплея Apex Legends. Загрузи видео, выбери модель и получи обработанный результат с bounding box-ами и опциональным исправлением растянутого разрешения.

## Возможности

- **Умная детекция:** Центрированная область поиска для лучшей производительности.
- **Поддержка растянутого разрешения:** Исправляет stretched-видео до пропорций 1:1 для точного инференса.
- **Синхронизация звука:** Обрабатывает переменный FPS и пропущенные кадры для сохранения синхронизации аудио.
- **Очередь задач:** Асинхронная обработка через FastAPI и Worker.
- **Выбор бэкенда инференса:** PyTorch или ускорение через TensorRT (примерно в 9 раз быстрее).

## Бэкенды инференса

Бэкенд выбирается в интерфейсе, над областью загрузки видео.

| | **PyTorch** | **TensorRT** |
|---|---|---|
| Подготовка | не нужна | собирает движок при первом запуске |
| Пайплайн | Ultralytics | целиком на GPU |
| Точность вычислений | FP32 | FP16 (по умолч.) или FP32 |

Скорость на 640x640:

| Модель | PyTorch FP32 | TensorRT FP32 | TensorRT FP16 |
|---|---|---|---|
| YOLOv8n (nano) | 59 FPS | 380 FPS | **526 FPS** |
| YOLOv8m (medium) | 50 FPS | 121 FPS | **278 FPS** |

> Замерено на RTX 3070 Ti, на реальном геймплейном ролике 1920x1080 @ 60 —
> 1200 кадров, медиана. На другом железе цифры будут другими.

В отличие от пути PyTorch, на TensorRT FP16 даёт реальный выигрыш — в 1.4 раза
на YOLOv8n и в 2.3 раза на YOLOv8m. Число найденных боксов при этом совпало с
FP32 кадр в кадр, так что точность по умолчанию терять не жалко. Почему FP16
помогает здесь и не помогает на PyTorch — в следующем разделе.

### Что показывает счётчик FPS

Число, вшитое в итоговое видео, — это **скорость в реальном времени**: сколько
кадров в секунду модель вытянула бы на живом источнике на этой видеокарте.
Чтение и запись видеофайла относятся к демке, а не к модели, и в счётчик не
входят. Поэтому сохранение результата идёт дольше, чем показывает счётчик, —
так и задумано.

### Почему TensorRT настолько быстрее

При обработке по одному кадру инференс YOLO упирается **не в вычисления, а в
запуск CUDA-ядер**: GPU успевает досчитать ядро раньше, чем Python поставит в
очередь следующее. Замер на YOLOv8n: время запуска ядер (11.37 мс) составило
весь форвард-пас целиком (11.30 мс). По той же причине FP16 ничего не даёт на
пути PyTorch — узкого места в арифметике просто нет, — хотя на большом matmul
та же видеокарта честно показывает трёхкратный выигрыш FP16.

По этой же причине FP16 начинает работать, как только подключается TensorRT.
Узкое место с запуском ядер убрано, ускорять остаётся именно арифметику — и
переключение, которое ничего не давало на PyTorch, здесь стоит 1.4–2.3 раза.
Чем тяжелее модель, тем заметнее: YOLOv8m выигрывает от FP16 больше, чем
YOLOv8n.

Бэкенд TensorRT убирает именно это узкое место, а не арифметику:

| Что сделано | Эффект |
|---|---|
| CUDA graph вместо запуска ядер по одному | движок 1.84 → 0.80 мс |
| Препроцессинг на GPU, кадр не покидает видеокарту | 1.20 → 0.17 мс |
| Отрисовка боксов на GPU вместо OpenCV | ~6 → 0.21 мс |

Отдельно: у BoT-SORT отключена компенсация движения камеры — для всех бэкендов.
Профайлер показал, что `calcOpticalFlowPyrLK` съедает 75% всего вызова
`track()`, то есть ~44 мс на кадр, в восемь раз больше самого инференса.
Отключение подняло трекинг с ~20 до ~165 FPS без заметной потери качества на
геймплее. Переопределение — в `backend/tracking.py`.

Итого **~1.9 мс на кадр** на YOLOv8n в FP16.

Трекинг остался на штатном BoT-SORT. Самописный GPU-трекер был опробован и
отброшен: он рисовал рамки на деревьях, где модель ничего не находила, и при
этом оказался *медленнее* — 2.03 мс против 0.49 мс, потому что сопоставление на
GPU требует синхронизации каждый кадр, а BoT-SORT работает на паре строк numpy.

### Как работает кэш движка

TensorRT компилирует модель в движок, оптимизированный под **фиксированный** размер
входа, поэтому движок привязан к конкретной комбинации настроек:

```
models/engines/apex_detect_v8n_v2.1_640x640_fp16.engine
                └──модель────────┘ └размер┘ └ точность
```

- При первом запуске с конкретной комбинацией движок собирается автоматически — это
  занимает несколько минут (~5 мин для YOLOv8n) — и **кэшируется внутри проекта**
  в папке `models/engines/`.
- Все последующие запуски с теми же настройками берут движок из кэша и стартуют сразу.
- Смена модели, размера Search Area или точности создаёт новую запись в кэше и
  вызывает однократную пересборку под неё. Ранее собранные движки остаются в кэше.
- Интерфейс до запуска показывает, готов ли уже движок или его ещё предстоит собрать.

Настройки движка (точность, workspace, принудительная пересборка) появляются в боковой
панели при выборе бэкенда TensorRT. Папка `models/engines/` добавлена в `.gitignore` —
движки привязаны к конкретной видеокарте и драйверу, поэтому всегда собираются локально
и не коммитятся.

> **Принудительная пересборка** нужна только после смены видеокарты или драйвера.

## Требования

- **GPU с поддержкой CUDA** — обязательно для инференса (рекомендуется NVIDIA)
- **CUDA 12.8** (или измени URL установки torch под свою версию)
- **Python 3.10+**
- **ffmpeg** установлен и доступен в `PATH`
- **TensorRT** *(опционально)* — только для ускоренного бэкенда, ставится из `requirements.txt`

## Установка

### 1. Клонировать репозиторий с подмодулями:
```bash
git clone --recurse-submodules https://github.com/PSImera/apex_enemy_detect_demo.git
cd apex_enemy_detect_demo
```

### 2. Создать и активировать виртуальное окружение

```bash
python -m venv .venv
```

**Linux / macOS:**
```bash
source .venv/bin/activate
```

**Windows (cmd):**
```cmd
.venv\Scripts\activate
```

**Windows (PowerShell):**
```powershell
.venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```bash
python -m pip install --upgrade pip
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
```

> Измени URL torch, если используешь другую версию CUDA.

Зависимости TensorRT в конце `requirements.txt` опциональны — их можно пропустить, если
планируешь пользоваться только бэкендом PyTorch. Они указаны как `tensorrt-cu12` для
CUDA 12.x; для CUDA 11 нужен `tensorrt-cu11`. TensorRT 11 не поддерживается: в нём
удалены API, которые до сих пор использует Ultralytics.

**Linux (Debian/Ubuntu) — системные библиотеки:**
```bash
sudo apt update
sudo apt install ffmpeg freeglut3-dev libgl1-mesa-dev libglu1-mesa-dev
```

**Windows — ffmpeg:**

Скачай с [ffmpeg.org/download.html](https://ffmpeg.org/download.html) и добавь `ffmpeg/bin` в `PATH`.
